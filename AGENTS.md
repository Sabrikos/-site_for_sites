# Vega Studio

Проект: PHP + PDO + MySQL/MariaDB + JavaScript/CSS. Сначала изучай существующую архитектуру и фактические пути выполнения; документация может отставать от кода. Не ломай работающие сценарии и не меняй дизайн без необходимости.

## Общие инварианты

- Цены и критичные данные определяет сервер/БД. Проверяй входные данные на сервере; клиентские суммы не являются источником истины.
- Используй prepared statements для SQL с параметрами пользователя.
- Не коммить секреты, `.env`, пароли, API keys и Telegram token; не выводи их в отчёты.
- Не выполняй разрушительные операции БД без необходимости и отдельного согласования конкретного действия.
- Не используй `git reset --hard`, `git clean -fd`, force push. Не удаляй чужие или незакоммиченные изменения. Перед правками проверяй `git status` и текущую ветку. При конфликтах изучай обе стороны и сохраняй полезные изменения обеих веток.
- После PHP-правок выполняй `php -l` для изменённых файлов; после JS-правок — `node --check` там, где формат файла это допускает. После существенных изменений проверяй затронутые основные страницы и сценарии. Не заявляй о проверке, которую не удалось выполнить.
- Рабочие уведомления команды должны идти в группу **Vega Studio | Support**, а не в личные сообщения администраторам. Секретные идентификаторы бери из локальной конфигурации без публикации.
- Обычные сообщения support-группы не должны попадать клиенту. Ответ маршрутизируется только при однозначном сопоставлении Reply/сообщения с `conversation_id` и проверке полномочий отправителя.
- Сохраняй Telegram routing, защиту от повторных updates и корректность handoff.
- AI не отвечает в `waiting_human`, `human` и `closed`; перед сохранением результата повторно проверяй состояние и актуальность generation. Возврат в `bot` должен быть явным.
- Vega Assistant не получает произвольный SQL, shell, filesystem или административные полномочия из пользовательского prompt.

## Координация агентов

Главный Codex координирует работу. Для содержательных задач делегируй независимый анализ подходящим нативным custom agents из `.codex/agents/`; для мелкой локальной правки достаточно главного Codex. Не запускай всех для каждого запроса.

| Агент | Когда привлекать |
| --- | --- |
| `frontend-reviewer` | HTML/CSS/JS, mobile, responsive, accessibility, UI/UX, overflow, анимации, frontend performance |
| `backend-reviewer` | PHP/PDO/БД, услуги, тарифы, корзина, заказы, админка, миграции, транзакции |
| `security-reviewer` | Auth, CSRF/XSS/SQLi, sessions/cookies, секреты, rate limits, webhook и production exposure |
| `telegram-reviewer` | Bot, webhook/polling, Support routing, Reply, assignment, typing, handoff, duplicates |
| `ai-reviewer` | Vega Assistant, LLM, context/history, fallback, prompt injection, state/generation races |

Передай каждому границы задачи, нужные файлы и требуемый результат. Reviewers анализируют read-only; исправления выполняет главный Codex после получения результатов, устранения противоречий и самостоятельной проверки критичных выводов. При лимите параллелизма запускай следующую группу после завершения предыдущей. Не имитируй запуски агентов, если инструмент недоступен: явно сообщи ограничение.

Совместимость: в проверенных CLI `0.162.0-alpha.2` и `0.162.0-alpha.17.2` текущая схема `collaboration.spawn_agent` не предоставляет селектор custom type. Если это сохраняется в новой сессии, используй реальные обычные subagents: явно поручай каждому прочитать соответствующий `.codex/agents/<имя>.toml` и применять его `developer_instructions` как инструкции делегированной задачи. Отчёт обязан отличать этот режим от автоматической нативной загрузки custom agents. Имена задач сами по себе не подключают профиль. Без доступного инструмента subagents выполняй анализ последовательно и явно сообщай, что делегирования не было.

Результат reviewer: просмотренные файлы, подтверждённые проблемы с `file:line`, условия воспроизведения, последствия, пробелы проверки. Отделяй наблюдения и гипотезы. Не запускай тесты с реальными отправками Telegram/LLM или записью в БД без проверки их побочных эффектов и разрешённого тестового окружения.
