# GigaChat: состояние интеграции

Подготовлен прямой транспорт GigaChat V1: OAuth Basic → access token, UUIDv4,
обновление после 401, проверка TLS, один system-контекст и native JSON schema.
GPT не используется как резервный провайдер GigaChat. При ошибке остаётся
существующая локальная консультация по каталогу.

Проверено 01.11.2026: создан личный проект «VegaStudio тест API», ключ сохранён
только в локальном .env. OAuth успешно выдал токен. При включённом VPN после
добавления двух точных direct-правил в JSON активного сервера получен ответ
GigaChat-2-Max:2.0.30.01 на синтетическое сообщение. Проверен синтетический
вопрос о тарифе лендинга: модель выбрала допустимый ID; числа цены и срока
не передаются ей из полей каталога, их продолжает добавлять backend.
Реальные посетительские сообщения НЕ включены (GIGACHAT_CHAT_ENABLED=0).
На локальном компьютере настроен отдельный PEM CA bundle приложения.
Переподключение VPN выполнили для применения правил; пользователь потребовал
больше не отключать VPN. VPN оставлен включённым; без нового указания не трогать.

В кабинете при создании проекта показано: коммерческий доступ для новых
подключений предоставляется через Cloud.ru, Freemium — личный тестовый доступ.
Этот тестовый ключ не является подтверждением допуска коммерческой эксплуатации.

## Настройки сервера

В локальном `.env` (не коммитить):

```dotenv
AI_PROVIDER=gigachat
GIGACHAT_CHAT_ENABLED=0
GIGACHAT_AUTH_KEY=
GIGACHAT_SCOPE=
GIGACHAT_MODEL=GigaChat-2-Max
GIGACHAT_CA_BUNDLE=
```

Scope копируется из своего API-проекта целиком: GIGACHAT_API_PERS,
GIGACHAT_API_B2B или GIGACHAT_API_CORP. Нельзя считать, что персональный
бесплатный аккаунт допускает использование на коммерческом сайте.
Ключ не следует отправлять в чат, клиентский JS или хранить в Git.

GIGACHAT_CHAT_ENABLED=1 разрешает реальные сообщения и их историю в GigaChat.
До согласования обработки персональных данных оставлять 0, даже при наличии ключа.
Секреты и токены транспорта не записываются в логи. Токен переиспользуется только
в памяти экземпляра клиента; межзапросный дисковый кеш не реализован.

Для TLS при необходимости задать PEM CA bundle по официальной инструкции;
проверку сертификата не отключать и не менять глобальное хранилище доверия.

## Условия, которые ещё не решены

- Стандартное корпоративное prepaid-соглашение, п.9.6, не предполагает
  обработку персональных данных посетителей. Российский API не заменяет
  подходящий договор и проектирование защиты данных.
- Текущий redact() не является обезличиванием. Фильтр ПД в этой задаче не менялся.
- Пересылка переписки в Telegram остаётся отдельным каналом; этот адаптер её не меняет.
- Политика сайта и бизнес-правила консультанта требуют отдельного согласования.
- Рабочий ответ модели и доступность модели аккаунту нельзя подтвердить без API-доступа.

## Проверки без внешних отправок

`php tests/gigachat.php` — fake HTTP, фиктивные ключи, без БД и сети.
`php assistant-test.php --live` — это уже реальная отправка синтетического
вопроса и публичного каталога, требует включённой конфигурации. Посетительскую
историю для теста использовать нельзя.
