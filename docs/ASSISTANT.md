## Как получается ответ

1. Browser отправляет сообщение в api/chat.php с токеном защиты формы и своей сессионной cookie.
2. PHP определяет диалог по сессии. Переданный посетителем чужой conversation_id не используется.
3. ChatService сохраняет сообщение и отмечает выполняющийся запрос. Одновременно разрешён только один AI-запрос на диалог.
4. AiAssistant читает последние сообщения этого диалога, активные services/tariffs и релевантные записи faq. В историю не входят другие диалоги, таблицы заказов, пароли или настройки сервера.
5. При наличии ключа модель получает системные правила, ограниченный контекст и историю. Она понимает естественную речь, несколько вопросов, сравнение и уточнения. Системные правила не содержат зашитых цен.
6. Модель возвращает JSON: объяснение, список ID тарифов и признак явного запроса человека. SQL, shell и административных инструментов у неё нет.
7. PHP проверяет JSON, типы, размер и наличие ID в переданном каталоге. Модели запрещено писать цены и числовые факты в объяснении. Названия, описания, цены, сроки и сумма комбинации добавляются PHP из повторно прочитанной БД.
8. Перед сохранением ответа ChatService повторно проверяет статус и ключ запроса. Если за это время подключился администратор, старый AI-ответ отбрасывается.

Контекст каталога ограничен 16000 символами; первыми включаются подходящие тарифы. Читается не более 60 активных тарифов и не более трёх подходящих FAQ. История по умолчанию ограничена 12 сообщениями; старые сообщения сокращаются до 1200 символов каждое, текущее сообщение передаётся полностью в пределах разрешённой длины.

Без ключа работает поиск по названиям, вариантам написания и предыдущим пользовательским сообщениям. Это резервный режим, а не настоящая нейросеть: он понимает предусмотренные сочетания, но не гарантирует понимание произвольной речи. Вопрос о неизвестных условиях направляется администратору.

Нейросеть не создаёт заказ по случайной фразе. Оформление проходит через существующие тарифы и корзину с подтверждением. Чат не даёт модели доступа на запись в БД.

## Передача человеку и статусы

Фразы «позови человека», «оператор», «соедини с менеджером» переводят диалог в waiting_human. Ответ «да» делает это только после сохранённого предложения позвать администратора. Отрицательный ответ не запускает передачу.

В waiting_human и human AI не отвечает. Подключение или ответ администратора переводит диалог в human. Кнопка «Вернуть ассистенту» ставит bot. Кнопка завершения ставит closed; посетитель больше не может отправлять сообщения в этот диалог.

Открытая видимая вкладка выбранного диалога обновляет присутствие администратора. Без обновлений статус «в сети» исчезает через 35 секунд. Набор текста отправляется с ограничением частоты и задержкой; индикатор исчезает через 7 секунд без обновления. Это не постоянно включённый статус.

В web-chat статус Assistant меняется сразу после отправки. Три точки анимируются CSS. Полный ответ приходит от PHP и появляется словами за 0,45–2,4 секунды. Это визуальный typewriter, не потоковая передача SSE от модели. При системной настройке уменьшения анимаций текст появляется сразу. Прокрутка уже написанного текста остаётся доступной.

## Telegram-уведомления

Сохранены TELEGRAM_BOT_TOKEN и TELEGRAM_ADMIN_CHAT_IDS. Новые заказы и запросы человека отправляются всем указанным администраторам. Ошибка уведомления не отменяет заказ и не возвращает диалог боту. Проверочная команда сообщает об успехе только при успешной отправке всем адресатам.

В уведомлении о диалоге передаются его номер и, для публичного HTTPS-адреса, кнопка открытия админки. Текст переписки в Telegram не передаётся: автоматическая проверка отклонила такую отправку из-за возможных личных данных. Переписка доступна после входа в админку.

Для localhost кнопка внешней ссылки не добавляется. Адрес 127.0.0.1 на телефоне или другом компьютере означает именно это устройство, а не компьютер владельца. Для совместной удалённой работы потребуется опубликованный сайт с HTTPS и правильный APP_URL.

## Безопасность и ограничения

Ключи хранятся серверно в .env; этот файл и bd.php игнорируются Git. Тестом подтверждено, что .env, SQL, логи и внутренние PHP-сервисы недоступны через новый локальный router.php. Старый сервер, запущенный без router.php, этой защиты не получает: остановите его и используйте обновлённый start-server.bat.

Ответы и пользовательские сообщения выводятся через textContent/HTML-экранирование. Для HTTP API включены проверка сессии, токена формы, источника, длины и типов полей. В логах AI сохраняются только тип ошибки/HTTP-статус, без ключа, переписки, raw-ответа и заголовка Authorization. HTTPS-проверка сертификата включена, перенаправления запросов провайдера выключены, ответ ограничен по размеру.

Промпт и локальная проверка отклоняют запросы секретов, внутренних инструкций и административных действий. Это защита в несколько слоёв, а не обещание, что языковая модель никогда не ошибётся: после подключения ключа нужна отдельная проверка качества реальных ответов. У модели нет инструментов выполнения, и факты о ценах добавляет сервер.

На сайте пока встречаются шаблонные контакты и юридические поля. Их нужно заменить подтверждёнными данными перед публикацией. Ассистент не использует примерный email из верстки как проверенный контакт.

### Подключить OpenAI

1. Откройте [страницу API-ключей OpenAI](https://platform.openai.com/api-keys), войдите в свой аккаунт и создайте ключ для проекта. Проверьте доступность API и настройки оплаты/лимитов аккаунта. Официальная инструкция: [Developer quickstart](https://developers.openai.com/api/docs/quickstart).
2. В локальном .env укажите ключ в AI_API_KEY. Не отправляйте ключ в переписку и не добавляйте его в Git. В .env.example остаются пустые поля ключей.
3. Добавьте или проверьте остальные настройки:

```ini
AI_API_KEY=
AI_MODEL=gpt-4.1-mini
AI_API_BASE_URL=https://api.openai.com/v1
AI_MAX_INPUT_LENGTH=2000
AI_MAX_HISTORY_MESSAGES=12
AI_MAX_OUTPUT_TOKENS=900
AI_MAX_REQUESTS_PER_DAY=100
```

Строка ключа выше намеренно пустая. Заполнить нужно только локальный .env. Конфигурация рассчитана на OpenAI и JSON Schema; формат сверён с [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [описанием модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

4. Перезапустите PHP-сервер.
5. Выполните один настоящий запрос с искусственным примером вопроса и публичным каталогом:

```powershell
& 'D:\Downloads\php-8.3.31-Win32-vs16-x64\php.exe' assistant-test.php --live
```

Успех реальной интеграции: Mode: llm и код завершения 0. Mode: fallback означает, что настоящий API-запрос не прошёл проверку; подробности без секретов находятся в storage/logs/app.log. Отсутствие ключа даёт код 2 без отправки запроса.

6. Проверьте в браузере составной вопрос про цветочный магазин, Лендинг Бизнес и AI-ассистента; затем «А сколько это займёт?», «Позови человека» и запросы изменить цену/раскрыть ключ. При статусах human и waiting_human API не вызывается.

Один вопрос делает максимум один внешний AI-запрос, без автоматических повторов. В резервном режиме и для распознанных запрещённых действий их нет. По умолчанию: 20 AI-запросов на диалог в час, 40 на IP в час и 100 на весь сайт в сутки. Дополнительно ограничены входной текст, история, контекст и выходные токены. Это ограничение количества запросов, а не точная денежная квота; денежный лимит задавайте у провайдера.

### Telegram

1. На компьютере владельца остановите существующий polling перед получением chat_id через getUpdates. В окне его запуска нажмите Ctrl+C и подтвердите остановку batch-файла, если Windows спросит.
2. Оба человека открывают @webstart_studio_bot и отправляют /start.
3. Владелец запускает команду, которая показывает ID полученных сообщений:

```powershell
& 'D:\Downloads\php-8.3.31-Win32-vs16-x64\php.exe' telegram-chat-ids.php
```

Если список пуст, отправьте /start повторно и снова выполните команду до запуска polling. Telegram хранит ожидающие обновления ограниченное время; получение через webhook и getUpdates взаимоисключается. См. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

4. В локальный .env владельца добавьте оба числовых ID через запятую:

```ini
TELEGRAM_ADMIN_CHAT_IDS=МОЙ_ID,ЕЁ_ID
```

5. Проверить отправку обоим администраторам:

```powershell
& 'D:\Downloads\php-8.3.31-Win32-vs16-x64\php.exe' telegram-test-notification.php
```

6. Убедитесь, что сообщение реально пришло вам обоим. Затем запустите единственный экземпляр polling:

```powershell
.\run-telegram-bot.bat
```

7. При работающем боте командой /id можно получить свой chat_id прямо в личной переписке с ботом, не запуская getUpdates отдельно. Команда /cancel отменяет незавершённое оформление.

8. Проверьте /start, /help, /services, /tariffs и /order. Созданный Telegram-заказ должен появиться в admin/orders.php. Заказ с сайта и запрос «позови человека» должны дать уведомление обоим.

Если токен ранее публиковался на скриншотах или стал доступен через старый сервер, замените его через BotFather и обновите только локальный .env.

## Перед публикацией

Используйте полноценный web-сервер и PHP-FPM, HTTPS, закрытый доступ к .env/storage/SQL/внутренним сервисам, отдельного пользователя БД и резервное копирование. Встроенный php -S подходит для локальной разработки и обслуживает запросы последовательно; долгий ответ API может задерживать остальные запросы. Проверенный router.php работает именно при запуске через обновлённый bat-файл. .htaccess предназначен для Apache с разрешёнными правилами rewrite; для Nginx нужны соответствующие запреты в конфигурации.

Укажите публичный APP_URL, заполните настоящие контакты и сведения владельца, выключите display_errors, выполните миграцию и повторите проверки. Не открывайте старый локальный сервер без router.php в интернет. Не запускайте один и тот же Telegram polling на двух компьютерах; для независимой разработки используйте отдельного тестового бота.

## Что нужно сделать напарнице

1. Найти в Telegram @webstart_studio_bot, открыть и нажать Start, затем отправить /start.
2. Если владелец уже запустил бота, отправить /id и сообщить владельцу полученный номер. Если бот ещё не запущен, владелец получит номер через telegram-chat-ids.php после её /start.
3. Владелец добавляет её номер рядом со своим в TELEGRAM_ADMIN_CHAT_IDS локального .env и перезапускает polling.
4. Владелец запускает telegram-test-notification.php. Оба проверяют, что получили сообщение.
5. Для получения уведомлений ей НЕ нужно запускать run-telegram-bot.bat, устанавливать PHP или получать AI API key. Бот работает на одном компьютере владельца либо на общем сервере.
6. Для ответа клиенту нужна доступная ей админка и собственные данные входа. Адрес 127.0.0.1 компьютера владельца на её устройстве не откроет его сайт.
7. Если она хочет запускать свою копию сайта, ей нужны код после вашего коммита/push, PHP, MySQL, локальная база, свой .env с её настройками БД и bd.php по образцу bd.example.php. Пароли и .env через Git не передаются.
8. Без AI-ключа её локальный чат использует резервные ответы. Для самостоятельных настоящих AI-запросов ей понадобится разрешённый для её среды API-ключ; для одних уведомлений он не нужен.
9. Не запускайте общий бот одновременно на её и вашем компьютерах. Для двух независимых сред разработки создайте второго тестового бота.
